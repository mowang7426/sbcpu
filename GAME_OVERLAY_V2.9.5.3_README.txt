V2.9.5.3 GameOverlay architecture fix

IMPORTANT:
The previous version drew the game banner inside SpringBoard's CPU window. That cannot produce a true in-game overlay and caused the large horizontal black pill shown in testing.

This version separates the game overlay into SBCPUGameOverlay.dylib. SpringBoard writes the latest notification to:
/var/mobile/Library/Preferences/com.yourname.sbcpufloating.gamebanner.plist
and posts Darwin notification:
com.yourname.sbcpufloating.gamebanner

SBCPUGameOverlay.dylib is injected into the configured game bundle IDs and creates its own transparent UIWindow above the game. The window's hitTest always returns nil, so game touch input passes through.

Initial target bundle IDs:
- com.tencent.speedmobile
- com.tencent.tmgp.speedmobile
- com.tencent.tmgp.qqspeed

If QQ飞车手游 on the user's device uses a different bundle identifier, add that identifier to SBCPUGameOverlay.plist and rebuild.

Target visual behavior in landscape:
- narrow black rounded vertical capsule on the left edge
- app icon/glyph, app name + sender, unread count
- slides in from left
- stays about 4 seconds
- slides out
- does not consume touch
